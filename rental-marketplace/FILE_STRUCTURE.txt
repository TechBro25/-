================================================================================
EXECUTION FLOW:
================================================================================

1. Start: npm start
   → backend/src/server.js
   → Loads backend/src/app.js
   → Connects to DB via backend/src/db.js
   → Mounts routes from backend/src/routes/*
   → Serves frontend files
   → Listens on port 3000

2. User visits http://localhost:3000
   → Serves frontend/index.html
   → Loads frontend/styles/main.css
   → Loads frontend/scripts/main.js
   → Fetches items via /api/items
   → Renders item grid

3. User clicks item
   → Navigates to /item/1
   → Serves frontend/item.html
   → Fetches /api/items/1
   → Fetches /api/reviews/item/1
   → Renders detail page

4. User creates booking
   → Submits form
   → POST /api/bookings
   → backend/routes/bookings.js handles
   → Validates via middleware/auth.js
   → Stores in database
   → Returns booking ID

5. Admin logs in
   → POST /api/auth/login
   → backend/routes/auth.js validates
   → Returns JWT token
   → Visits /admin
   → Serves frontend/admin.html
   → Fetches /api/admin/stats
   → Requires admin role check

DATABASE STRUCTURE:

rental_marketplace.db (SQLite):

┌─────────────────────────────────────────────┐
│ users                                       │
├─────────────────────────────────────────────┤
│ id, email, password_hash, full_name,        │
│ phone, role, is_verified, created_at        │
└─────────────────────────────────────────────┘
        │
        ├──── items (owner_id FK)
        │     • title, price_per_day, images, rating
        │
        ├──── bookings (renter_id FK, owner_id FK)
        │     • item_id, dates, status, payment_status
        │
        ├──── reviews (user_id FK)
        │     • item_id, rating, comment, media
        │
        ├──── messages (sender_id FK, receiver_id FK)
        │     • booking_id, channel, body
        │
        └──── kyc_documents (user_id FK)
              • verification_code, status, verified_at

SECURITY FEATURES:
================================================================================

✅ Password Hashing
   • bcrypt with 10 salt rounds
   • Passwords never stored in plain text

✅ JWT Authentication
   • Secret key from environment
   • 7-day token expiry
   • Verified on protected routes

✅ Rate Limiting
   • 5 requests per 15 minutes on auth endpoints
   • Prevents brute force attacks

✅ SQL Injection Protection
   • All queries use parameterized statements
   • No string concatenation in queries

✅ Input Validation
   • Email format validation
   • Password length requirements
   • Date range validation

✅ Role-Based Access Control
   • User vs Admin roles
   • Owner-only item updates
   • Admin-only moderation

✅ File Upload Security
   • File type validation (images/videos only)
   • File size limits (10MB max)
   • Sanitized filenames
